# 🤖 GPT 기반 자동 SKU 매칭 시스템

## 개요

쿠팡 2P 데이터 처리 시 매칭되지 않는 신규 옵션을 GPT가 자동으로 분석하여 SKU_master 테이블에 추가하는 지능형 시스템입니다.

## 🎯 작동 원리

### 1단계: 1차 매칭
기존 방식대로 SKU_master 테이블과 직접 매칭을 시도합니다.

### 2단계: GPT 분석 (매칭 실패 시)
매칭에 실패한 옵션들을 GPT가 다음 3가지 케이스로 분류합니다:

#### 케이스 1: 개수변경 자동생성 (같은 패키지)
- **특징**: **같은 용량/사이즈**의 제품을 **개수만 변경**
- **예시**:
  - ✅ "500ml 1병" → "500ml 2병"
  - ✅ "10개입" → "20개입"
  - ✅ "300g 1개" → "300g 3개"
  - ❌ "500ml" → "1L" (용량 변경은 케이스 3!)
- **ID 생성 규칙**: `기존ID-1`, `기존ID-2`, `기존ID-3`...
- **데이터 처리**: 기존 제품 데이터 복사 후 원가/정가를 개수 비율로 조정 (2개 = 2배 원가)
- **⚠️ 중요**: 패키지 용량/사이즈가 바뀌면 케이스 3입니다!

#### 케이스 2: 환불재판매
- **특징**: 환불/반품된 상품을 재판매
- **키워드**: "환불", "반품", "리퍼", "중고", "B급" 등
- **ID 생성 규칙**: `기존ID-A`, `기존ID-B`, `기존ID-C`...
- **데이터 처리**: 기존 제품 데이터 복사 후 원가/정가에 할인 적용 (70-80%)

#### 케이스 3: 신규상품 (패키지 변경 포함)
- **특징**:
  - 완전히 새로운 브랜드/제품
  - **패키지 용량/사이즈가 변경된 경우**
- **예시**:
  - 새 브랜드 상품
  - "500ml" → "1L" (용량 변경)
  - "100g" → "200g" (사이즈 변경)
  - → 패키지가 달라지면 원가 구조가 다르므로 신규 상품으로 분류
- **ID 생성 규칙**: 새로운 ID 생성 (현재 최대값 + 1)
  - 접두사 형식: `S060704101` → `S060704102`
  - 숫자만: `200` → `201`
- **데이터 처리**: GPT가 상품명, 카테고리 등을 분석하여 새 레코드 생성
- **원가 처리**: 원가 정보가 없으면 0으로 설정 (손익계산 오류 방지)

### 3단계: SKU_master 자동 생성
GPT 분석 결과에 따라 새로운 SKU_master 레코드를 자동 생성하고 DB에 삽입합니다.

**ID_master 형식 지원**:
- 알파벳 접두사 + 숫자 형식 (예: `S060704101`)
- 순수 숫자 형식 (예: `42`, `100`) - 하위 호환성
- Case 1, 2는 기존 ID에 suffix 추가 (예: `S060704101-1`, `S060704101-A`)
- Case 3는 숫자 부분만 증가 (예: `S060704101` → `S060704102`)

### 4단계: 재매칭 및 저장
새로 생성된 SKU로 매칭을 완료하고 sales_report_coupang_2p 테이블에 저장합니다.

### 5단계: 원가 업데이트 보고서 생성
신규 생성된 SKU가 있을 경우, 원가 업데이트 안내 보고서를 자동 생성합니다.

**보고서 내용**:
- 신규 생성된 SKU 목록 (ID, 상품명, 분류, 현재 원가)
- 처리 일시 및 파일명

**출력 형식**:
- 화면 출력: 콘솔에 전체 보고서 표시
- 파일 저장: `원가_업데이트_필요_[타임스탬프].txt`
- 용도: 담당자에게 원가 업데이트 요청 시 전달용

**보고서 예시**:
```
======================================================================
⚠️  신규 SKU 원가 업데이트 필요
======================================================================

파일: 쿠팡_2p_전체_2024_12.xlsx
처리일시: 2024-12-15 14:30:00
신규 생성 SKU: 3건

다음 SKU들이 자동 생성되었으나 원가 정보가 없습니다.
담당자에게 아래 내용을 전달하여 SKU_master 테이블 원가 업데이트를 요청하세요.

----------------------------------------------------------------------
신규 생성된 SKU 목록:
----------------------------------------------------------------------

1. ID: S060704102
   상품명: 코카콜라 500ml 2병
   분류: 개수변경 자동생성 (같은 패키지)
   기반 ID: S060704101
   현재 원가: 0원 ⚠️ 업데이트 필요

2. ID: S060704103
   상품명: 펩시콜라 1.5L
   분류: 신규상품 (용량변경 포함)
   현재 원가: 0원 ⚠️ 업데이트 필요

======================================================================
⚠️ 위 내용을 담당자에게 전달하여 원가 업데이트를 요청해주세요.
======================================================================
```

## 📋 설정 방법

### 1. OpenAI API 키 발급
1. https://platform.openai.com/api-keys 방문
2. API 키 생성
3. `.env` 파일에 추가:
```env
OPENAI_API_KEY=sk-proj-xxxxxxxxxxxxxxxxxxxxx
OPENAI_MODEL=gpt-4o-mini
```

### 2. 필수 패키지 설치
```bash
pip install -r requirements.txt
```

### 3. 실행
```bash
python main.py
```

## 📊 데이터베이스 변경사항

### SKU_master 테이블
- **변경 없음**: 기존 스키마 유지
- **자동 레코드 추가**: GPT가 분석한 신규 상품 자동 삽입

### 새로운 ID_master 형식
- 기존: `1`, `2`, `3`, ... (숫자만)
- 추가:
  - `42-1`, `42-2` (수량변경)
  - `15-A`, `15-B` (환불재판매)
  - `201`, `202` (신규상품)

## ❓ FAQ

**Q: GPT 분석이 느린가요?**
A: 상품 1개당 약 1-2초 소요됩니다. 10개 미매칭 상품은 약 10-20초면 처리됩니다.

**Q: GPT가 잘못 분류하면?**
A: 확신도(confidence)가 낮으면 수동 확인을 권장합니다. 생성된 SKU_master를 나중에 수정할 수 있습니다.

**Q: 기존 데이터에 영향이 있나요?**
A: 없습니다. 새로운 SKU만 추가되며 기존 데이터는 변경되지 않습니다.

**Q: 쿠팡 1P는 지원하나요?**
A: 현재는 쿠팡 2P만 지원합니다.

**Q: 신규상품(케이스 3)의 원가가 0으로 들어가는데 괜찮나요?**
A: 네, 손익계산 시스템에서 NULL 오류를 방지하기 위해 0으로 설정됩니다. 추후 실제 원가를 SKU_master 테이블에서 수동 업데이트하면 됩니다.

## 🔧 문제 해결

### "OpenAI API key not found"
→ `.env` 파일에 `OPENAI_API_KEY` 추가

### "GPT 시스템 초기화 실패"
→ `pip install openai` 실행 후 재시도

### "Rate limit exceeded"
→ OpenAI API 사용량 초과. 잠시 후 재시도하거나 유료 플랜 업그레이드
